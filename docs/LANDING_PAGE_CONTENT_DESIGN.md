## 1. 先定页面职责

首页和着陆页不能做成两份换汤不换药的长页面。

| 页面 | URL | 页面角色 | 唯一任务 | 主 CTA |
|---|---|---|---|---|
| 产品首页 | `/` | Core / Conversion Hub | 让跨境服装卖家在首屏理解产品、相信生成边界并开始试用 | 免费生成 1 条试用视频 |
| 三图专题着陆页 | `/three-images-to-clothing-video` | Topic Pillar / Campaign Landing | 解释为什么三张同款素材能让镜头更可控，并承接搜索或广告流量 | 用三张图开始生成 |

首页负责品牌、总价值和转化。专题着陆页只讲清“三张图”和“稳定机制”，不重复价格表、完整 FAQ 或所有产品能力。

## 2. 核心定位

### 2.1 目标用户

- 有现成商品图，但没有稳定视频拍摄产能的跨境服装卖家。
- 需要为 Shopify 商品页、TikTok、Reels 快速制作单 SKU 视频的独立站团队。
- 更在意服装版型、细节和交付是否可控，而不是追求夸张 AI 特效的运营人员。

### 2.2 核心承诺

> 上传同一件服装的三张有效素材图，系统先检查素材，再只选择素材支持的镜头，生成 8、16 或 24 秒商品宣传视频。

“稳定”在页面中必须解释为一套约束流程，而不是结果保证：

1. 对正面、侧面、背面等主体视角做任务内一致性检查；细节图是否属于同一件服装由上传者确认。
2. 根据正面、背面、侧面和细节素材决定可用镜头。
3. 缺少证据的镜头不开放，不让提示词绕过规则。
4. 生成后抽帧质检，通过后才交付。

### 2.3 禁止使用的承诺

- 不使用“100% 不变形”“零幻觉”“保证一致”“任意三张图都能生成”。
- 不暗示一张正面图可以补出背面、隐藏结构、面料纹理或 360 度展示。
- 不把本地 10+ 条技术测试写成大规模用户验证或公开成功率。
- 没有真实数据前，不放虚构客户评价、虚构品牌 Logo 或虚构生成数量。
- 商品展示、商品旋转和真人转身不是同一个风险等级；Beta 能力不能伪装成默认能力。

## 3. 内容与视觉总纲

### 3.1 Visual thesis

采用克制的商品编辑风：真实服装视频占据首屏，三张原始素材作为后续证据出现；用黑、白、暖灰建立工具感，以品牌红只标记主操作和关键约束。

### 3.2 Content plan

- Hero：一句话说明“三张同款服装图 -> 一条商品视频”。
- Support：直接展示三张输入图和同一条真实输出视频。
- Detail：解释素材边界、镜头推荐、风格选择和质检机制。
- Final CTA：从一个 SKU 开始，不让用户先研究模型、模板或提示词。

### 3.3 Interaction thesis

- 首屏真实成片静音循环播放；加载失败或减少动态效果时使用同一视频的清晰 poster。
- 滚动到“三张素材”时，三张原图依次进入，对应的视频镜头时间点同步高亮，帮助用户理解输入与输出关系。
- CTA 和素材图只做短促的位移、边框或播放状态反馈，不用漂浮卡片、光球和无意义视差。

### 8.2 为什么是三张图

**H2**  
`一张图告诉模型“是什么”，三张图告诉系统“能展示到哪里”`

**正文**  
`服装视频最容易出问题的不是运动不够大，而是背面、版型和细节被模型擅自补全。三张同款素材让系统有机会先核对主体，再为不同镜头找到对应依据。`

**证据对应关系**

| 素材 | 能支持的内容 | 不能自动推断的内容 |
|---|---|---|
| 正面主图 | 正面轮廓、可见图案、正面慢推或平移 | 背面结构、隐藏开衩、背部印花 |
| 背面或侧面图 | 对应视角的真实结构 | 未上传角度之间的连续旋转 |
| 细节图 | 已拍到的面料、领口、袖口或印花 | 未拍到的材质纹理和工艺 |

### 8.3 推荐的三图方式

**H2**  
`先选择三图方式，再按位置上传`

**方案 A：三图商品展示（推荐）**  
`正面主图 + 背面图 + 细节图`  
适合大多数服装 SKU，用于商品页和常规社媒展示。

**方案 B：商品旋转（付费 Beta）**  
`无真人商品正面 + 侧面 + 背面`  
仅在三张同款一致性通过后开放；不会被风格预设自动选中。

**方案 C：真人模特转身（付费 Beta）**  
`同一模特、同一件服装的正面 + 侧面 + 背面`  
需要服装与模特在本次任务中同时通过一致性检查，并要求上传者拥有肖像与商业宣传授权。

**方案边界**  
`Beta 方案不是默认能力。素材不满足时，系统会要求补图或改用低风险展示，不会硬生成旋转和转身。`

### 8.4 四道稳定控制

**H2**  
`从上传到交付，每一步都收窄不确定性`

1. `上传定位`：每张图进入明确位置，不让系统猜它是正面、背面还是细节。
2. `同款责任与检查`：上传者确认三张图属于同一 SKU；系统检查主体视角的任务内一致性，细节图同款由上传者确认；真人方案同时检查任务内模特一致性。
3. `镜头权限`：先过滤不可用镜头，再让风格预设参与推荐；提示词不能越权。
4. `成片质检`：分段生成后抽帧检查，拼接为完整视频并记录交付状态。

**短句强调**  
`稳定不是让模型更大胆，而是让它少做没有证据的决定。`

### 8.5 真实案例

**H2**  
`看三张原图如何变成一条完整视频`

**左侧/上方**

**右侧/下方**

- 成片时长：按真实样例填写
- 画面比例：按真实样例填写
- 生成状态：`已通过质检`

**案例说明**  
`这是一次真实工作流结果。不同服装、素材质量和镜头组合会产生不同结果。`

### 8.6 适合与不适合

**H2**  
`先判断你的素材是否适合`

**适合**

- 同一 SKU 有三张清晰、主体完整的商品图。
- 需要快速制作商品页或社媒测款视频。
- 接受系统根据素材边界调整镜头，而不是强行指定不存在的角度。

**不适合**

- 三张图不是同一件服装，或颜色、版型差异明显。
- 只有正面图，却要求完整背面、360 度或真人转身。
- 需要精确复刻复杂表演、剧情广告或未拍摄的强场景。

### 8.7 FAQ 摘要

**三张图必须是哪三张？**  
默认推荐正面、背面和细节图。商品旋转与真人转身有各自固定的三图要求，并处于付费 Beta。

**三张图一定能保证服装完全不变吗？**  
不能。生成式视频仍存在不确定性；产品通过主体视角一致性检查、镜头限制和生成后质检降低风险，而不是承诺零误差。

**没有背面图可以生成背面吗？**  
不可以。系统不会把正面图推断成真实背面结构。

**可以免费试吗？**  
新用户可生成 1 条 8 秒低清、无音频、带水印试用视频，且只使用低风险镜头。

**延伸链接**

## 13. 转化与内容验收

### 13.1 文案验收

- 用户只看 H1、副文案和 CTA，就能说出“上传什么、得到什么、为什么更可控”。
- 所有“三张图”表述都带有“同一件服装”或明确的三图协议，不写“任意三张”。
- “稳定”至少一次被解释为检查、限制和质检，不作为无条件保证。
- 免费试用限制在首次 CTA 附近可见，不等到价格页才披露。
- 无背面图、无细节图、无场景图时的限制与 PRD 一致。
- 页面不暴露普通用户无需理解的 DeepSeek、PixVerse、Veo、Cloud Run 或模型路由细节。

### 13.2 视觉验收

- 首屏必须使用真实服装成片或清晰 poster，不使用抽象渐变或纯装饰图。
- 三张输入素材和输出视频必须属于同一个真实案例。
- 桌面与手机首屏都能看到 CTA，并露出下一章节内容。
- 视频、图片和文案不重叠；最长中文按钮文案在 320px 宽度下不截断。
- 支持 `prefers-reduced-motion`，视频失败时仍能理解页面。

### 13.3 数据验收

至少记录：

- `landing_viewed`：区分 `homepage` 与 `three_images_landing`。
- 主 CTA 点击：记录页面、登录状态和 CTA 位置。
- 真实样例播放：记录开始播放与播放 50%。
- 从专题页进入 FAQ、Pricing 和 Workspace 的出口。
- 注册 -> 上传三张图 -> 完成分析 -> 提交生成 -> 下载的完整漏斗。

没有公开样本量前，只展示机制和真实案例，不展示成功率百分比。

## 14. 实施前必须统一的产品口径

当前 PRD 与现有工作台/首页存在口径冲突：PRD 的部分段落仍写“至少一张正面图，其他素材可选”，而当前首页、工作台和本次核心定位要求按一种协议上传三张图。

实施本设计前应明确并同步以下一条：

- 如果 MVP 强制三张图：更新 PRD、FAQ、上传校验和所有错误文案，统一为“三张同款有效素材”。
- 如果 MVP 仍允许一张图：Hero 不能写“必须三张”，应改为“推荐三张”，且专题页 CTA 不能承诺三图流程是唯一入口。

基于当前用户要求与现有工作台实现，本方案默认采用“按协议强制上传三张图”。
